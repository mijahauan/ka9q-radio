# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

*ka9q-radio* is a multichannel software-defined radio for Linux by Phil Karn, KA9Q. Its core is `radiod`, a daemon that reads an A/D stream directly from SDR front-end hardware and runs hundreds of independently tunable digital downconverter/demodulator channels in real time using a fast-convolution (overlap-save) filter bank. All signal and control I/O uses IP multicast. Written in C (gnu11), built with GNU Make. There is no test suite.

## Build commands

```sh
make -j              # build everything (top level recurses into src, aux, share, service, rules, docs, config)
make -C src radiod   # build a single program
make -C src BUILD=debug        # debug build (-g, no -O3/-DNDEBUG)
make -C src SANITIZE=1         # address/UB sanitizers
make -C src NATIVE=1           # -march=native
make MACPREFIX=/opt/local      # macOS: force a package prefix (default: Homebrew, else MacPorts)
sudo make install    # installs binaries, systemd units, udev rules, /etc/radio configs
make clean
```

Front-end driver plugins are gated by `ENABLE_*` flags (e.g. `ENABLE_RX888=1`, `ENABLE_ALL=1`); defaults are set in the top-level Makefile (`ENABLE_SDRPLAY=0` because its API is proprietary). Primary target is Debian Linux, but the whole package including `radiod` also builds and runs on macOS — see `docs/INSTALL-macos.md`. On Darwin the top-level Makefile leaves the `ENABLE_*` defaults unset and `src/Makefile` instead probes for installed vendor headers, so a driver is built only if its library is present; explicit `ENABLE_*=` still wins. `MACPREFIX` selects the package prefix (Homebrew if installed, else MacPorts). Darwin-specific code is confined to `#ifdef __APPLE__` blocks — mDNS uses the native `dns_sd` API instead of Avahi (`avahi.c`, `avahi_browse.c`), multicast joins must set `ss_len` (`multicast.c`), services run under launchd instead of systemd (`service/`, `aux/radiod-launchd`), and udev/sysctl.d/logrotate.d/cron.d installs are skipped.

`src/config_paths.h` is generated by the Makefile from `git` metadata and install paths; it is a build product (as are `*.o`, `*.d`, `*.a`, `*.so`).

To run during development without systemd: `radiod -v YOUR_FILE.conf`, then `control` (channel status/control) or `monitor MCAST_IP` (audio) from another terminal. Running from an uninstalled build tree needs `library = .../x.so` in the hardware section and `mode-file = .../share/presets.conf` in `[global]`, since both otherwise resolve under the install prefix. Production runs as systemd instances: `systemctl start radiod@foo` reads `/etc/radio/radiod@foo.conf`; on macOS the equivalent is `sudo radiod-launchd foo`.

## Architecture

All sources live flat in `src/`. Three static convenience libraries are shared across programs (see `src/Makefile`):
- `libradio.a` — misc, multicast, rtp, config (iniparser wrapper), sched (realtime priority / CPU affinity)
- `libdsp.a` — filter (the fast-convolution engine), iir, window, osc, sincospi
- `libstatus.a` — status TLV encode/decode

### radiod (the core)

Objects: `main.o audio.o avahi.o modes.o fm.o wfm.o linear.o spectrum.o radio.o n0.o radio_status.o rtcp.o` + the libs.

- **Front-end drivers are dlopen'd plugins** (`airspy.so`, `rx888.so`, `rtlsdr.so`, `sig_gen.so`, …). `radio.c` loads the .so named by the config's hardware section and resolves a `<name>_setup` symbol; each driver fills the `struct frontend` function pointers `setup/start/shutdown/tune/gain/atten` defined in `radio.h`. One front end per radiod instance; a single global `Frontend` exists per process. `sig_gen` is a synthetic front end for testing without hardware.
- **Fast-convolution filter bank** (`filter.c`): one shared forward FFT over the raw A/D stream; each channel does its own frequency-domain mixing/decimation and inverse FFT. Channel filter impulse responses must be shorter than the configured overlap interval. FFTW wisdom matters for performance (see `docs/FFTW3.md`, `fft-gen`).
- **Channels**: `struct channel` (radio.h), keyed by RTP SSRC, each with its own `demod_thread`. Four demodulator types: `LINEAR_DEMOD` (SSB/CW/DSB/AM/IQ), `FM_DEMOD`, `WFM_DEMOD` (broadcast stereo), `SPECT_DEMOD`/`SPECT2_DEMOD` (spectrum analysis pseudo-demod) — implemented in `linear.c`, `fm.c`, `wfm.c`, `spectrum.c`. Presets (mode defaults) come from `presets.conf` via `modes.c`. Channels are created statically from config sections or dynamically via the control protocol (`create_chan`/`lookup_chan` by SSRC).
- **Networking**: demodulated output is RTP over IP multicast (`rtp.c`, `multicast.c`, `audio.c`); command/status is a custom TLV protocol on UDP port 5006, one multicast group per radiod instance — first byte 0=STATUS, 1=COMMAND (`status.c`, `radio_status.c`; protocol spec in `docs/ka9q-api.md`). Streams are advertised via avahi/mDNS (`avahi.c`).

### Everything else

Separate programs consume radiod's multicast streams: interactive clients `control` (ncurses channel control) and `monitor` (audio playback); recorders `pcmrecord` (obsoletes pcmcat/pcmspawn via `--stdout`/`--exec`) and `wd-record`; decoders/daemons `aprs`, `aprsfeed`, `cwd` (morse), `packetd` (AX.25), `jt-decoded`; utilities `tune`, `powers`, `metadump`, `opussend`, `pcmsend`. Because everything is multicast, they can run on any host on the LAN and be restarted independently.

`config/` holds example radiod configs, `service/` systemd unit templates (`.service.in`, paths substituted at install) plus the launchd plist template used on macOS, `aux/` udev rules and sysctl settings plus the `radiod-launchd` helper, `docs/` man pages and the real documentation (`ka9q-radio.md`, `-2.md`, `-3.md` for config reference; `ka9q-api.md` for the control protocol; `INSTALL.md` for prerequisites).

## Conventions and gotchas

- **Never add `-ffast-math` or `-ffinite-math-only`**: NaN is used throughout as the "parameter not set" sentinel (e.g. in channel/status parameters).
- macOS's fortified libc traps on things glibc tolerates. `config_getstring()` returns the *default pointer itself* when a key is absent, so passing a struct field as the default and then `strlcpy`ing into that same field is a self-overlapping copy: harmless on glibc, `SIGTRAP` on Darwin. There was one such bug in `loadpreset()`.
- Config files are INI format parsed with iniparser; a `radiod@foo.conf.d/` directory of `*.conf` fragments is read after the main file, sorted by name.
- radiod instance config lives in `/etc/radio/`; `make install` will not overwrite existing configs there.
- Dependency files (`.d`) are auto-generated via `-MMD -MP` and included by the Makefile; when adding a source file, add it to `CFILES` in `src/Makefile` and to the relevant link target.
